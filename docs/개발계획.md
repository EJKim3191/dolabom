# 돌아봄 개발 계획: 1차 산출물에서 2차까지

1차 산출물(2026-11-15 제출)은 차량용 앱의 기획서, 디자인, 그리고 `mock`·`pleos` 빌드 APK입니다.
이 문서는 지금 무엇이 되고, 무엇이 가짜이며, 2차 PT 심사(12월 3~4일)까지 무엇을 어떤 순서로 만들지 정리합니다.
서비스 전체 그림과 화면 구성, 디자인은 [기획서](기획서.md)에 있습니다.

## 1. 메인 기능 요약

| # | 기능 | 한 줄 설명 | 어디서 |
|---|---|---|---|
| F1 | 뒷좌석 상태 판단 | 소리·움직임·안전띠·차량 신호를 모아 편안함, 잠듦, 지루함·불안, 멀미, 더위, 안전띠 풀림, 무반응, 하차 후 방치 중 하나로 판단 | 차량 앱 `core` |
| F2 | 한 문장 안내와 음성 | 상태가 바뀌면 큰 문장으로 보여 주고, 살펴봐야 할 때만 한 줄을 읽어 준다. 같은 안내는 되풀이하지 않는다 | 차량 앱 |
| F3 | 쉼터 제안과 경유지 | 멀미·지루함이면 가까운 쉼터를 제안하고, 받아들이면 경유지로 요청한다 | 차량 앱 → 내비 |
| F4 | 하차 후 방치 3단계 | 운전자 알림 → 60초 뒤(또는 28℃) 가족 알림 → 180초 뒤(또는 32℃) 119 안내 | 차량 앱 → 핸드폰 앱 |
| F5 | 뒷좌석 영상 | 핸드폰을 앞좌석 머리 받침에 고정해 촬영하고, 차량 화면에 실시간으로 보여 준다. 영상·소리 인식의 입력원 | 핸드폰 앱(카메라 모드) → 차량 앱 |
| F6 | 가족 알림과 응답 | 가족 폰이 상태와 긴급 알림을 받고, 전화·확인·119로 응답한다 | 차량 앱 → 서버 → 핸드폰 앱(가족 모드) |
| F7 | 차량 신호 | Pleos Vehicle SDK로 뒷문·주차·운전자·실내 온도를 읽는다 | 차량 앱 `pleos` 빌드 |

## 2. 현재 개발 정도 (1차 산출물 기준)

| 기능 | 상태 | 실제로 되는 것 | 가짜 또는 없는 것 |
|---|---|---|---|
| F1 상태 판단 | **구현** | `core` 패키지 순수 Kotlin. 단위 테스트 38개 통과 | 입력값이 시연 패널의 가짜 값 |
| F2 안내·음성 | **구현** | Android 기본 음성 합성으로 읽어 줌. 음성 엔진이 없으면 화면 기록만 | 없음 |
| F3 쉼터·경유지 | 부분 | 제안 화면, 받아들이면 기록에 남음 | 장소·거리는 예시. 내비게이션 연동 없음 |
| F4 방치 3단계 | 부분 | 단계 판단, 시간·온도 조건, 화면 표시 | 가족 알림과 119 안내는 문구만. 실제 전송 없음 |
| F5 뒷좌석 영상 | 디자인만 | 차량 화면에 영상 자리와 "연결 전" 안내 | 폰 카메라 앱, 전송, 영상·소리 인식 모두 없음 |
| F6 가족 알림 | 디자인만 | 핸드폰 화면 4장 디자인 | 핸드폰 앱 코드, 서버, 푸시 없음 |
| F7 차량 신호 | 부분 | `pleos` 빌드에서 뒷문 열림 읽기 (컴파일 확인, 에뮬레이터 실행 전) | 주차·운전자·실내 온도는 가짜 |
| 디자인 | **구현** | 블랙 + 파랑 디자인을 Compose 코드에 반영. 공통 크롬, 좌석 도식, 상태 링, 지도 | 서체는 기기 기본(Noto Sans KR 번들 전) |
| 빌드·검증 | **확인** | `mockDebug`, `pleosRelease` 빌드 성공. 휴대폰 에뮬레이터에서 화면 3개 흐름 확인, 크래시 없음 | Pleos Connect 에뮬레이터 실행, 실제 차량 미확인 |

한 줄로: **판단과 안내는 진짜, 눈과 귀(영상·소리)와 바깥 연결(가족·내비)은 아직 가짜.**

## 3. 개발 방향

1. **눈과 귀를 먼저 붙인다.** 지금 가장 큰 공백은 입력이다. 별도 장비 없이 집에 있는 여분 폰을 뒷좌석 카메라로 쓰는 쪽(F5)이 가장 빠르고, 차 안에서만 처리한다는 원칙과도 맞는다.
2. **판단 로직은 그대로 둔다.** `core`는 입력원이 바뀌어도 손대지 않는다. 폰 카메라의 인식 결과를 `RearSeatSensor` 인터페이스로 흘려 넣기만 한다.
3. **차 밖 연결은 최소로 시작한다.** 가족 알림(F6)은 상태 한 줄과 차량 신호만 보낸다. 영상은 어떤 경우에도 차 밖으로 내보내지 않는다.
4. **차량 신호는 쓰는 것만 늘린다.** 뒷문 다음으로 주차·운전자 탑승·실내 온도 순. 권한도 쓰는 것만 선언한다.

## 4. 2차까지 개발할 사항

### 1단계 · 폰 카메라와 차량 화면 영상 (F5 앞부분)

| 할 일 | 내용 | 산출물 |
|---|---|---|
| 핸드폰 앱 골격 | 새 모듈 `phone/`. 화면 P1(카메라 세팅·촬영), P2(홈). `core`를 같이 쓴다 | 폰 APK |
| 차량 연결 | 차량 화면에 QR·6자리 코드 표시, 폰에서 입력해 짝짓기. 차 안 Wi-Fi 다이렉트(대안: USB 테더링) | 연결 흐름 |
| 영상 전송 | 폰 후면 카메라 → 차량 앱. WebRTC 또는 RTSP, 720p 15fps 목표, 지연 0.5초 이내 | 차량 화면 2b에 실시간 영상 |
| 세팅 가이드 | 프레임 안에 카시트, 얼굴 보임, 밝기, 소리 상태 칩 | P1 화면 동작 |
| 끊김 처리 | 카메라 끊기면 차량 화면에 "카메라 연결 끊김", 차량 신호 기반 판단은 계속 | |

### 2단계 · 영상·소리 인식 (F5 뒷부분, F1 입력 교체)

| 할 일 | 내용 | 산출물 |
|---|---|---|
| 얼굴·자세 인식 | ML Kit 얼굴 감지(온디바이스)로 얼굴 보임·눈 감김·머리 움직임 → `MotionCue`(차분함·잠듦·뒤척임) | `RearSeatSensor` 실제 구현 |
| 소리 분류 | 온디바이스 오디오 분류(YAMNet 계열)로 울음·낑낑거림·짖음·조용함 → `SoundCue` | |
| 안전띠 | 1차는 카시트 버클 영역의 색·형태 변화로 추정. 정확도가 낮으면 "확인해 주세요"로만 안내 | |
| 반려동물 | 헐떡임(입 벌림 빈도), 짖음. 아이와 같은 파이프라인, 레이블만 다름 | |
| 시연 패널 | 실제 인식이 붙은 뒤에도 남겨 두되 "시연" 표시를 분명히 | |
| 검증 | 인식 결과가 `core` 판단으로 이어지는 통합 테스트. 오탐이 잦은 상태(멀미)는 2분 지속 조건을 유지 | 테스트 |

### 3단계 · 가족 알림 (F4 2·3단계, F6)

| 할 일 | 내용 | 산출물 |
|---|---|---|
| 서버 | 상태·단계·차량 신호·위치만 중계하는 작은 API. 영상 경로 없음 | |
| 푸시 | FCM. 2단계는 일반 푸시, 3단계는 긴급(전체 화면) 푸시 | P3 화면 동작 |
| 가족 등록 | 차량에서 초대, 사람마다 받을 단계 선택 | P4 화면 동작 |
| 응답 | 폰에서 전화·확인·119 → 차량 기록에 "가족 확인" 표시 | 차량 화면 반영 |
| 위치 | 차량 위치(Pleos 위치 API 또는 폰 GPS) | 지도 표시 |

### 4단계 · 차량 신호와 내비게이션 (F7, F3)

| 할 일 | 내용 |
|---|---|
| 차량 신호 확장 | Pleos Vehicle SDK에서 주차(기어 P·시동), 운전자 좌석 착좌, 실내 온도 읽기. 권한은 쓰는 것만 추가 |
| Pleos Connect 에뮬레이터 검증 | `pleos` 빌드를 2560 × 1440 에뮬레이터에서 실행해 뒷문 신호와 화면 배율 확인 |
| 경유지 | NaviHelper SDK로 실제 쉼터 검색과 경유지 추가 |

### 함께 할 것

- 프라이버시 문서: 어떤 데이터가 어디까지 가는지 표로 README에 둔다.

## 5. 일정 (2차 PT 심사 12월 3~4일 기준)

1차 결과 발표는 11월 23일, 2차 PT 심사는 12월 3~4일입니다. 1차 제출 다음 날인 11월 16일부터 PT 전날까지 17일 동안 아래 순서로 진행합니다.

| 기간 | 할 일 | 확인 기준 |
|---|---|---|
| 11/16~11/20 | 1단계 · 폰 앱 골격, 연결, 영상 전송 | 차량 화면에 폰 카메라 영상이 0.5초 안에 보인다 |
| 11/21~11/25 | 2단계 · 얼굴·소리 인식, `RearSeatSensor` 교체 | 시연 패널 없이 잠듦·울음이 판단으로 이어진다 |
| 11/26~11/29 | 3단계 · 서버, 푸시, 가족 등록, 응답 | 방치 2단계에 가족 폰이 울리고, 확인이 차량 기록에 남는다 |
| 11/30~12/01 | 4단계 · 차량 신호 확장, Pleos 에뮬레이터 검증 | 뒷문·주차·온도가 실제 신호로 들어온다 |
| 12/02 | 통합 시연, 문서 정리 | 2차 APK와 PT 시연 준비 |
| 12/03~12/04 | 2차 PT 심사 | 차량 화면에서 실제 입력으로 시연한다 |

기간이 짧아서, 일정이 밀리면 뒤 단계부터 범위를 줄입니다. 3단계는 푸시와 확인 응답만, 4단계는 뒷문과 실내 온도만 먼저 끝냅니다.

## 6. 위험과 대비

| 위험 | 대비 |
|---|---|
| 차 안 Wi-Fi 다이렉트가 차량 OS에서 막힘 | USB 테더링 대안. 둘 다 안 되면 폰에서 인식까지 하고 결과값만 블루투스로 보낸다(영상은 폰 화면에만) |
| 온디바이스 인식 정확도 | 멀미·무반응처럼 위험한 판단은 지속 시간 조건을 길게, 안내 문구는 "확인해 보세요" 수준 유지 |
| 에뮬레이터·차량에서 성능 | 영상은 720p 15fps 상한, 인식은 초당 2회 |
| 가족 알림 오발송 | 운전자가 60초 안에 돌아오면 2단계를 보내지 않음. 보낸 뒤 해제되면 "해제됨" 푸시 |
