# 돌아봄 기획서

**뒤를 맡겨 주세요. 당신은 앞만 보고 갈 수 있도록.** 가장 안전하고 편안한 공간이 될 수 있도록, 돌아봄이 함께합니다.

운전 중 뒤를 돌아볼 수 없는 부모와 반려인을 대신해, 뒷좌석의 아이와 반려동물 상태를 보고 듣고 알려주는 AI 동승 케어 서비스입니다.
차량 화면에서 판단하고 안내하는 **차량용 앱**과, 뒷좌석에 고정해 아이를 촬영하는 카메라이자 차에 없는 가족이 상태를 받아 보는 **핸드폰 앱** 두 가지로 이루어집니다.

디자인 캔버스: https://claude.ai/artifact/VRnHniHt6CrhZH6USsF5CB (차량 화면 4장, 핸드폰 화면 4장)

## 1. 문제와 대상

| 항목 | 내용 |
|---|---|
| 문제 | 운전자는 주행 중 뒷좌석을 볼 수 없다. 아이가 멀미를 하거나 안전띠를 풀어도, 반려동물이 더위에 헐떡여도 알아채기 어렵다. 하차 후 아이를 차에 두고 내리는 사고는 몇 분 만에 위험해진다. |
| 대상 | 카시트에 아이를 태우는 부모, 반려동물과 이동하는 반려인. 그리고 차에 타지 않은 다른 가족(배우자, 조부모). |
| 원칙 | 진단이 아니라 "확인해 보세요" 수준의 안내. 영상과 소리는 차 안에서만 처리하고 저장하거나 차 밖으로 보내지 않는다. |

## 2. 제품 구성: 두 가지 화면

| | 차량용 앱 (Pleos Connect) | 핸드폰 앱 (가족·보호자용) |
|---|---|---|
| 쓰는 사람 | 운전자 | (카메라 모드) 뒷좌석에 고정된 운전자 가족의 여분 폰 / (가족 모드) 차에 없는 가족, 또는 운전자 본인(하차 후) |
| 하는 일 | 폰 카메라에서 온 뒷좌석 영상과 차량 신호로 상태를 판단하고, 한 문장으로 보여 주고 읽어 준다. 영상을 실시간으로 보여 준다. 쉼터를 제안하고 경유지를 요청한다. 하차 후 방치를 3단계로 올린다. | **카메라 모드**: 앞좌석 머리 받침에 고정해 뒷좌석을 촬영하고, 영상과 소리를 차량 앱에 보낸다. 세팅 가이드(프레임 안에 카시트, 밝기, 얼굴 보임)를 준다. **가족 모드**: 차량이 판단한 상태 한 줄과 차량 신호를 받아 본다. 방치 2·3단계 알림을 받고, 운전자에게 전화하거나 119 안내를 보거나 "가고 있어요"로 응답한다. 누가 알림을 받을지 정한다. |
| 입력 | 폰 카메라 영상·소리(차 안 Wi-Fi 다이렉트 또는 USB), Pleos Vehicle SDK 차량 신호(뒷문 구현, 나머지 예정) | 카메라 모드: 후면 카메라, 마이크. 가족 모드: 차량 앱이 보낸 상태·신호·알림 |
| 출력 | 화면(실시간 영상 포함), 음성 안내, 내비게이션 경유지(예정) | 카메라 모드: 영상·소리 스트림. 가족 모드: 푸시 알림, 화면, 전화 연결 |
| 화면 규격 | 가로 1280dp 기준, 2560 × 1440 화면에서 2배 | 390 × 844 세로 |

차량용 앱이 판단의 주체입니다. 핸드폰 앱은 두 역할을 합니다. 차 안에서는 뒷좌석 카메라(눈과 귀)이고, 차 밖에서는 결과를 받아 보는 가족의 창입니다. 별도 카메라 장비 없이 집에 있는 여분 폰으로 시작할 수 있다는 점이 핵심입니다. 카메라 폰이 꺼져 있거나 연결이 끊겨도 차량 앱의 차량 신호 기반 판단(뒷문, 하차 후 방치)과 안내는 그대로 돌아갑니다.

## 3. 핵심 시나리오

### 3-0. 뒷좌석 카메라 세팅 (핸드폰 앱 → 차량 앱)

1. 핸드폰 앱에서 "뒷좌석 카메라"를 열고 차량 앱과 연결한다(차량 화면의 QR 또는 6자리 코드).
2. 앞좌석 머리 받침에 폰을 고정한다. 화면의 틀 안에 카시트가 들어오게 맞추면 얼굴 보임·밝기·소리 상태가 초록으로 바뀐다.
3. "인식 시작"을 누르면 차량 화면(2b)에 실시간 영상이 뜨고, 그때부터 영상·소리 인식 값이 차량 앱의 판단에 들어간다.
4. 영상은 차 안 기기 사이에서만 오가고, 어느 쪽에도 저장하지 않는다. 폰 화면은 촬영 중 어둡게 꺼진다.

### 3-1. 주행 중 상태 안내 (차량 앱)

1. 동승자(아이 또는 반려동물)와 부르는 이름을 고르고 "지켜보기 시작"을 누른다.
2. 1초마다 뒷좌석 인식 값과 차량 신호를 모아 상태를 판단한다. 편안함, 잠듦, 지루함·불안, 멀미, 더위, 안전띠 풀림, 무반응, 하차 후 방치.
3. 상태가 바뀌면 화면의 큰 문장이 바뀌고, 살펴봐야 할 상태면 한 줄을 음성으로 읽어 준다. 같은 안내는 되풀이하지 않는다.
4. 운전자는 2번 화면(상태 요약)과 2b 화면(영상 크게)을 오갈 수 있다. 주행 중에는 영상 위에 상태 한 문장을 겹쳐 보여 줘서 영상을 들여다보지 않아도 된다.

### 3-2. 멀미 → 쉼터 제안 → 경유지 (차량 앱)

1. 뒤척임과 낑낑거림이 이어지면 "멀미하는 것 같아요"로 알림 화면이 뜬다.
2. 가까운 졸음쉼터를 제안한다. "들렀다 가자"를 누르면 경유지로 요청하고, "계속 갈게요"를 누르면 닫는다.
3. 요청은 기록에 남는다. 내비게이션(NaviHelper SDK) 연동은 다음 단계다.

### 3-3. 하차 후 방치 3단계 (차량 앱 → 핸드폰 앱 연동)

| 단계 | 조건 | 차량 앱 | 핸드폰 앱 |
|---|---|---|---|
| 1단계 | 주차 + 운전자 하차 + 뒷좌석에 동승자 | 화면과 음성으로 운전자에게 알림 | (받지 않음. 운전자가 바로 돌아오는 경우가 대부분) |
| 2단계 | 1단계 뒤 60초, 또는 실내 28℃ 이상 | 가족에게 알림을 보냈다고 표시 | 푸시 알림. 차량 위치, 방치 시간, 실내 온도, 뒷문 상태. 버튼: 운전자에게 전화 · 확인(가고 있어요) · 119 신고 |
| 3단계 | 1단계 뒤 180초, 또는 실내 32℃ 이상 | 119 신고 안내 | 긴급 푸시. 119 신고 버튼을 맨 위로 |

폰에서 "확인 · 가고 있어요"를 누르면 차량 앱 기록에 "가족 확인"이 남고, 운전자가 돌아와 뒷문을 열면 양쪽 모두 해제됩니다.

## 4. 화면 구성

### 차량용 앱 (4장)

| 화면 | 구성 |
|---|---|
| 1. 동승자 선택 | 왼쪽: 질문 "오늘 뒷좌석에는 누가 타나요?", 아이·반려동물 선택 카드, 이름 입력, 음성 안내 예시, "지켜보기 시작". 오른쪽: 위에서 본 좌석 도식(뒷좌석 왼쪽 강조), 차량 연결 상태, 차량 신호·뒷좌석 인식·프라이버시 요약. |
| 2. 주행 중 뒷좌석 상태 | 왼쪽: 원형 상태 링과 큰 문장, 소리·움직임·안전띠, 기록. 오른쪽: 뒷좌석 영상 자리(폰 카메라 연결 전에는 안내만), 좌석 도식과 차량 신호 목록(주행·운전자·뒷문·실내 온도), 시연 패널, 주행 종료. |
| 2b. 주행 중 · 뒷좌석 영상 | 왼쪽 큰 칸: 폰 카메라 실시간 영상. 위에 "실시간 · 폰 카메라", "저장 안 함 · 차 안에서만", "얼굴 인식 중" 표시. 아래에 상태 한 문장과 소리·움직임·안전띠 요약, "작게 보기", 소리 듣기. 오른쪽: 좌석 도식(머리 받침의 폰 위치 표시), 카메라·주행·뒷문·온도, 기록, 주행 종료. |
| 3. 알림과 쉼터 제안 | 왼쪽: 상태 점과 알림, 큰 문장, 설명, 소리·움직임·온도, 버튼("들렀다 가자" / "계속 갈게요" 또는 "확인했어요"). 오른쪽: 제안 장소 지도, 또는 하차 후 방치 3단계. |

네 화면은 공통 크롬을 쓴다. 왼쪽 72dp 세로 레일(동승자·뒷좌석 상태·알림·기록·설정)과 48dp 상단 바(앱 이름, 동승자, 음성 안내 켬·끔, 시각).

### 핸드폰 앱 (4장)

| 화면 | 구성 |
|---|---|
| P1. 뒷좌석 카메라 세팅·촬영 | 카메라 미리보기 전체 화면. 네 모서리 틀과 얼굴 자리 안내, "카시트가 틀 안에 들어오게 맞춰 주세요", 얼굴 보임·밝기·소리 상태 칩, 카메라 전환·인식 시작·손전등, 연결된 차량 표시, "영상은 차 안에서만 오가고 저장하지 않아요". |
| P2. 홈 · 지금 뒷좌석 | 연결된 차량과 주행 정보, 상태 링과 큰 문장, 소리·움직임·안전띠, 차량 신호(뒷문·온도·운전자), 오늘 기록. |
| P3. 긴급 알림 수신 | "아이가 차에 남아 있어요", 차량 위치 지도, 방치 시간·실내 온도·뒷문, 3단계 진행, 버튼(운전자에게 전화 / 확인·가고 있어요 / 119 신고). |
| P4. 가족 알림 설정 | 연결된 차량, 알림 받을 사람(초대), 이 폰에서 받을 알림(2단계·3단계·주행 시작/종료·상태 변화), 프라이버시 안내. |

아래 탭 바: 지금 · 알림 · 기록 · 가족.

## 5. 연동 설계

| 항목 | 내용 |
|---|---|
| 흐름 1 · 카메라 | 카메라 폰 → 차량 앱. 차 안에서 Wi-Fi 다이렉트(또는 USB)로 직접 잇고, 서버를 거치지 않는다. 영상·소리 인식은 차량 앱(또는 카메라 폰) 안에서 돌고 결과값만 판단에 쓴다. |
| 흐름 2 · 가족 알림 | 차량 앱 → 서버 → 가족 폰(푸시). 폰의 응답(확인, 전화 시도)은 서버를 거쳐 차량 앱 기록에 남는다. |
| 보내는 데이터 (가족 폰) | 상태 한 줄(headline), 심각도, 방치 단계, 차량 신호(주차·운전자·뒷문·실내 온도), 차량 위치, 시각. 영상과 소리는 보내지 않는다. |
| 안 보내는 데이터 | 뒷좌석 영상, 소리, 인식 중간값은 차 밖으로 나가지 않는다. 가족 폰에는 상태 한 줄과 차량 신호만 온다. 카메라 폰에도 저장하지 않는다. |
| 연결 | 차량 앱에서 QR 또는 6자리 코드로 폰을 연결한다. 같은 폰을 카메라로도, 가족용으로도 쓸 수 있다. 한 차량에 가족 여러 명을 등록할 수 있고, 사람마다 받을 단계를 고른다. |
| 끊김 | 카메라 폰이 끊기면 차량 화면 영상 자리에 "카메라 연결 끊김"을 띄우고 차량 신호 기반 판단(뒷문, 하차 후 방치)만 이어 간다. 가족 폰이 꺼져 있어도 차량 앱의 판단과 안내는 그대로 돌아간다. 2단계 알림을 못 보냈으면 차량 화면에 "보내지 못했어요"를 표시한다. |
| 기술 | 공통 판단 로직은 `core` 패키지(순수 Kotlin)를 그대로 쓴다. 폰 앱은 같은 모델로 상태를 그린다. 푸시는 FCM, 서버는 상태와 응답만 중계한다(다음 단계). |
